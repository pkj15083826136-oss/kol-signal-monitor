# Phase 4：用户逐笔确认交易与状态跟踪

日期：2026-09-19（Asia/Shanghai）

## 已实现

- 交易状态机覆盖报价、阻止、过期、精确额度授权、授权确认、钱包签名、广播、receipt 确认、拒签和失败终态；非法跳转直接拒绝。
- EVM 执行器只调用浏览器钱包的 `eth_sendTransaction`。ERC-20 allowance 不足时先发起等于本次 `sellAmount` 的精确授权，receipt 成功后才请求 swap；没有无限授权入口。
- Solana 执行器接口只接受用户钱包提供的 `signAndSendTransaction` 与确认方法；服务端不持有 signer，也不接收私钥或助记词。
- Jupiter 准备接口用已校验的原始报价和用户公钥换取待签名交易，只将序列化交易返回浏览器钱包；接口受测试网/主网门禁控制，不接收签名结果或密钥。
- 主网总开关与逐链开关必须同时开启；缺失或格式错误均 fail closed。测试网由独立开关控制。
- 新增 `user_trades` 表。金额使用最小单位文本；EVM 地址和哈希在 D1 边界前规范化；仅拿到交易哈希后才允许写入 pending/confirmed/failed 状态，链与哈希唯一保证幂等更新。
- 交易记录入口显式拒绝私钥、助记词、signature 和 signed transaction 字段。
- 详情页保持桌面约 65/35、右侧吸顶，手机单列；补齐买卖、原生币/稳定币、快捷金额/卖出比例、滑点、摘要与本钱包记录区域。

## 默认安全状态

- `FEATURE_TRADE_MAINNET=false`，四条逐链主网开关均为 false/缺失。
- 未配置 Reown、聚合器 key、RPC 与 allowlist 时不能获得可执行报价或广播。
- 当前交付不包含自动交易、定时交易、托管钱包、服务端签名或无限授权。
- 本阶段未使用真实钱包、测试网资产或主网资金，也未发送真实企业微信测试消息。

## 自动化覆盖

- 全局/逐链 Feature Flag 双重门禁；余额不足、报价过期与错链阻止。
- 精确额度授权、授权失败不继续、拒签、swap receipt 失败、RPC 失败与 Solana 确认失败。
- 最小单位换算无浮点数、卖出百分比预留手续费。
- 状态机合法/非法跳转、交易记录规范化与敏感字段拒绝。

## 上线前仍需人工验收

见 `EXTERNAL_SETUP.md` 与 `FINAL_ACCEPTANCE.md`。测试网需要项目所有者的钱包、测试币和逐笔签名；首次主网交易需另行明确确认，且一次只放行一条链。
