# Codex 接管开发说明

## 一、项目目标

从约 884 个整理后的 KOL/聪明钱包地址以及 GMGN 动态 KOL 中，发现多个独立钱包在短时间内共同新建仓的代币。目标不是追踪成熟主流资产，而是尽早发现“创建时间短、市值较低、流动性可交易、KOL人数持续增加”的新币。

产品当前生产版本只负责监控、分析、网页展示和企业微信通知，不执行交易。项目所有者已批准规划“钱包连接 + 用户逐笔确认的手动买卖”新范围，完整边界见 `docs/TRADING_UPGRADE.md`；自动交易、服务端代签和私钥托管仍不在范围内。

2026-09-21 新增的 `/radar` 是独立的土狗雷达只读/Paper 模块。它的硬过滤、评分、AI审核、D1迁移和禁用钱包骨架见 `docs/RADAR_PHASE_1_ACCEPTANCE.md`。Paper 状态机不签名、不授权、不广播；不得把它误认为真实自动交易已获准。

## 三、一次监控周期

1. GitHub 采集器选择一条链。
2. 分别读取 GMGN KOL 与 smartmoney 交易流。
3. 将交易标准化并只保留固定监控池或 GMGN 动态 KOL。
4. `trades` 通过交易ID去重。
5. `token_wallets` 累计每个钱包的余额、买入额和首次买入时间。
6. 统计余额大于零的独立钱包数。
7. 调用 `lib/signal-policy.ts` 执行首次信号过滤。
8. 达到新阈值时生成 `signals`，必要时调用 xAI。
9. 保存热门帖子、持仓快照并发送企业微信。
10. 页面每15秒刷新 `/api/signals`。

## 四、不可破坏的业务规则

- 阶段：6、18、38、58 人。
- 同一钱包重复买入只计一人。
- 卖出后余额归零则不计当前持仓人数。
- 6人和38人阶段调用X搜索；18和58复用最近分析。
- 每次X搜索最多保存3条相关原创热门帖。
- 首次信号：市值超过2000万美元且创建超过10天时排除。
- 高市值但创建时间无法验证时保守排除。
- WETH、WBTC、USDT、USDC等成熟基础资产排除。
- 简介只能来自官方/行情元数据；AI分析不能冒充官方简介。
- 明确时间统一为北京时间。

## 五、关键实现选择

### 代币身份

名称、简称必须以合约匹配的 GMGN/DexScreener 数据优先。Ave 适合提供持币数、TVL、价格和K线，但出现过 BONK 合约被错误标成 TOGETHER 的情况。`lib/token-identity.ts` 保存必要的已验证修正。

### 创建时间

`lib/market.ts` 从 GMGN、Ave 和 DexScreener 读取候选时间，并采用最早的有效值。第三方请求失败时可能得到0，因此高市值且时间未知必须保守过滤。

### Ave额度

首次信号和详情页可调用 Ave。常规快照应使用公共行情回退，避免持续消耗 CU。新增批量任务前必须估算请求量。

### AI与推文

xAI 使用一次X搜索，最多三条帖子，输出中文短分析。38人阶段再次搜索是为了修正早期叙事不足。不要扩大为无限搜索或线程递归。

## 六、页面约定

- 列表只以简称作为主标题，不显示全称占行。
- 合约旁提供复制按钮。
- 新信号置顶、高亮7秒，15秒自动刷新。
- 详情页显示官方简介、独立AI分析、5/15分钟K线、KOL趋势和热门帖子。
- 所有文本容器必须支持长合约地址换行，移动端不得横向溢出。

## 七、优先改进路线

1. 为 `signal-policy.ts` 增加自动化边界测试。
2. 在数据库中保存 `token_created_at`、`market_data_source` 和 `identity_source`，使过滤可审计。
3. 增加“被过滤候选”审计表，记录排除原因而不是静默丢弃。
4. 为数据源增加健康度、延迟、成功率和额度消耗面板。
5. 把钱包池拆分为高质量KOL、普通KOL、聪明钱包并做加权信号，而不仅是人数。
6. 建立历史回测：记录首次6人时市值、流动性、后续1h/6h/24h最大涨幅和最大回撤。
7. 用回测结果校准信号质量评分，再考虑任何交易功能。
8. 如果追求秒级预警，将GitHub定时采集迁移为常驻服务或链上事件流。
9. 钱包与手动交易升级必须按 `docs/TRADING_UPGRADE.md` 的 Phase 0—5 分阶段实施，先只读连接和报价，再经测试开启小额主网广播。
